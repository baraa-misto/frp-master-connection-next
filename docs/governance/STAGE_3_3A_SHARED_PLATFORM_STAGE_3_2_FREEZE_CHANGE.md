# Stage 3.3A shared-platform Stage 3.2 freeze change

## Frozen behavior affected by shared symbols

Stage 3.3A adds a new connector family through shared exports, API routing/client code,
the unified connection selector, and the existing multi-row orchestration module. The
accepted Tee request/response meaning, geometry, result aggregation, fingerprints,
frontend workflow, and presentation remain unchanged.

## Boundary transition

The old multi-row boundary assembled an automatic member-end demand only inside the
existing multi-row orchestration request path. The new reusable boundary
`evaluate_multirow_connection_with_resolved_demand` accepts one already-resolved,
typed demand and forwards that exact object to the existing Stage 2.5B/2.6A handoff.
The existing caller retains its original path; Stage 3.3A uses the seam independently
for each physical clip-angle interface.

Shared package exports, route/client registration, and the connection selector receive
additive Stage 3.3A symbols. They do not change Direct or Tee defaults or payloads.

## Stage 3.3A reason

One single physical clip angle has two independent interfaces that need the verified
multi-row resistance engine without reconstructing demand or duplicating a calculation
engine. The additive seam preserves object identity and makes the authority boundary
explicit.

## Tee regression evidence

Full backend, frontend, integrated, and object-isolated suites retain all Tee golden,
exact-fingerprint, geometry, material, fastener, preview/design, viewport, and freeze
tests. The connection selector tests retain Direct as default and the existing Tee
selection behavior. Exact final counts are recorded in the Stage 3.3A completion
report after committed verification.

The Stage 3.2 manifest and its controlled artifact hashes are unchanged. The annotated
tags `stage-2.3-interface-geometry-freeze` and `stage-3.2-tee-connection-freeze` are
not moved, rewritten, or recreated; their frozen source objects are audited from the
immutable tags while the separately controlled active successor source tree is audited
from the staged/committed Stage 3.3A state.

R1 diagnoses the preview defect at the backend boundary: the accepted clip-angle
response identified the selected connected profile correctly but reduced every family
to one generic display plate. The frontend already consumed the accepted latest

and the existing placed-component visualization mapper into shared application seams.

W/I, or RHS physical elements, resolved basis, and material-region axes for both Brace
and Beam roles. Tee retains compatibility aliases for its existing test seams and uses
the same extracted implementation.

## Stage 3.3A-R3 preview geometry versus design-limitation separation

R3 corrects only clip-angle status classification and presentation. The backend now
publishes explicit geometry validity and physical geometry-invalid reasons separately
from design readiness, method applicability, unsupported normal action, and the
connector-body `NOT_EVALUATED` limitation. The frontend consumes those explicit
fields and no longer treats the first warning as a geometry-invalid reason. A valid
current preview therefore replaces the rendered scene even when an explicit design
check is unavailable; actual interference, hole-containment, surface, trim, and
bolt-path failures remain fail-closed and may retain the last valid scene.
