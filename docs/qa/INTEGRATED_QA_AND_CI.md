## Local integrated QA

From the repository root on the reviewed Windows environment, run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-all.ps1
```

The script derives every path from `$PSScriptRoot`, preserves and restores the caller's
working directory, exposes native command output, checks each exit code, and stops at
the first failure. It validates `HANDOFF_MANIFEST.json`, bootstraps and checks the
backend, bootstraps and checks the frontend, runs both npm audits, runs `git diff
--check`, and requires an empty Git index before reporting success.

## GitHub Actions execution

`.github/workflows/ci.yml` is named `CI` and runs on:

- pushes to `main`;
- pull requests targeting `main`; and
- manual `workflow_dispatch` requests.

Concurrency uses one group per workflow and Git ref and cancels an older in-progress
run for the same ref. The workflow has top-level `contents: read` permission only.
Checkout disables credential persistence. The workflow references no repository
secret, environment, artifact upload, package publication, release, deployment, Git
commit, or Git push.

## Backend job

The `backend` job runs independently on `ubuntu-24.04` and `windows-2025`, uses
`fail-fast: false`, and has a 25-minute timeout. It uses `actions/checkout@v7` and
`actions/setup-python@v7` with Python 3.14.6. From `backend/`, it:

1. prints Python and pip versions;
2. installs `requirements/requirements-dev-py314.lock.txt` with `--require-hashes`
   and `--only-binary=:all:`;
3. installs the local package editable with `--no-deps --no-build-isolation`;
4. runs `pip check`, Ruff format, Ruff lint, strict mypy, and pytest with the configured
   100% line-and-branch coverage gate;
5. checks Uvicorn and Alembic CLI availability; and
6. smoke-tests runtime and optional persistence imports, including the psycopg binary
   implementation.

The backend lock was generated on Windows and remains provisional. If an exact hashed
wheel is unavailable on Linux, the Linux job must fail visibly. Hash enforcement and
the binary-only policy must not be weakened; the failure becomes evidence for a
separate cross-platform-lock decision.

## Frontend job

The `frontend` job runs independently on the same two runners, with `fail-fast: false`
and a 25-minute timeout. It uses `actions/checkout@v7` and `actions/setup-node@v7` with
Node 24.18.0 and `package-manager-cache: false`. From `frontend/`, it prints Node/npm
versions and runs `npm ci`, `npm ls --all`, lint, strict TypeScript, Vitest coverage,
the production build, the full npm audit, and the runtime-only npm audit.

`frontend/package-lock.json` remains the authoritative Stage 0.2.3 tree. CI uses
`npm ci`; it never runs `npm install`, forced resolution, `npm audit fix`, or lock
regeneration. Build and coverage outputs are not uploaded.
