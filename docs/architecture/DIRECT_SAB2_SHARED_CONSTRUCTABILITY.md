# Direct SAB2 shared two-bolt constructability

SAB2 adds the backend geometry contract `SHEAR01-DIRECT-SAB2-GEOMETRY-V1`
on the existing Direct candidate. It does not establish structural qualification,
activate first-row/Supporting W methods, or alter the protected engines.

## Routes and authority

All three POST routes under `/api/v1/direct-two-bolt/` use the existing trusted
identity dependency. `preview` accepts the strict typed legacy Direct request,
alignment, spacing and explicit geometry context. It reconstructs proper physical
frames and exactly two collinear centers, evaluates those same centers against
both members, and returns an account-bound geometry snapshot handle.

`design-check` reconstructs eligibility on the server. Route A is the unchanged
unmarked brace workflow. Route B requires an identical accepted physical layout,
unchanged native method guards and no known negative constructability margin.
It freshly calls the existing MAT1 design handler. Original bolt/row IDs remain
in its 3D view; the audit explicitly maps neutral B1/B2 labels to those IDs.
Route C has no structural result, unity ratio, first-row inference or heel N/A.
All support-aligned and unmapped repositioned layouts use Route C.

`geometry-review` verifies account, family and current-request fingerprint
against the sealed snapshot. Its title and every page say geometry/constructability
only. Existing engineering export rejects geometry handles, and old input-only
snapshot endpoints reject grafted SAB2 contracts. Snapshot authentication is
software provenance, not a professional engineering seal.

## Geometry semantics

Inputs are inches or millimeters; the kernel uses exact Decimal inch quantities
and 64-digit calculation contexts. Proper-frame representation precision is the
existing governed contract. Negative clearance is never clamped to zero.
The selected physical face, shaft axis, actual head/nut seating surfaces and
disconnected rear W outstands remain distinct. The reusable face/strip kernel
supports a Channel control without activating a production Channel connection.

The actual submitted Angle loaded/unloaded end definition governs its finite
member. Supporting-member ends require explicit existing end declarations.
A display window is not a physical end. The fallback source preserves its raw
single-station anchor and records the geometry-only translation to the submitted
two-station unloaded-end definition. It cannot relax the resistance router.

Separate outcomes describe hole containment, shaft/rear-web clearance, washer
seating, known obstructions, represented hardware bodies, installation access and
aggregate constructability. Known negative margins dominate aggregate fit.
Exact contact is conditional. Unknown actual fillets, head/nut shapes, tools,
clocking, cuts or neighboring assemblies remain explicit; unknown is not zero.
Scalar root exclusions and finite cylinders/boxes are bounded declared envelopes.
The viewer renders declared convex cuts and envelopes from the evaluated snapshot;
its faceted display does not replace the analytic clearance calculations.

Fixed-midpoint comparison changes only alignment. Bounded seating regions retain
separate outstand assignments. Proposals are rechecked for the same geometry and
known obstacles and disclose `M_G = M_P + (P-G) x F` as a reference diagnostic.
They establish no new per-bolt demand or resistance. Apply is explicit and uses
the backend's exact absolute offset strings. A proposal is not a global optimum
or installation proof.

## Currency and reports

The input key binds physical geometry, materials, conditions and options. Changes
abort pending design, invalidate reports and clear old results. Account-bound
report snapshots reject mismatched current input. Late responses cannot restore
obsolete results. Camera and review display-unit changes are presentation only.

The geometry PDF prints computed face coordinates, spacing, signed margins,
fit states, limitations and the analytic audit. The complete native visualization,
typed input and proof are also retained byte-for-byte in the PDF attachment
`SAB2_complete_technical_audit.json`, with its size and SHA-256 printed in the
technical appendix. Repeated printed subtrees use explicit earlier-path aliases;
engineering evidence is retained.
